# MATMA JavaScript — owner-approved amendments and coverage boundaries

This file is portable with the skill. Read the separately bundled `MATMA_Seven_Architectural_Rules.md` first. The original seven rules remain normative **except for the explicit symbol-identity amendment to Rule 1**; the testing isolation boundaries are unchanged.

1. **Symbol-level Rule 1:** named publicly accessible functions, classes and export bindings are distinct MATMA units regardless of their containing file. A file may contain multiple units and named private helpers. Private helpers remain indexed for dependency/impact but receive no standalone mirrored unit tests. Class methods belong to their class. One public symbol has its own unit, interaction, mock and YAML manifest mirror under the original source filename.
2. **Strict tiers:** unit exactly one real symbol, all collaborators mocked; interaction exactly two real collaborators, all others mocked; business real internal workflow with mocked external infrastructure; regression real participating systems/datasets, no mocks. Business and regression are nonmirrored and explicitly registered.
3. **Pure JavaScript only:** `.js` ESM/CommonJS, `.mjs`, `.cjs` and traditional `<script>` JS. `.jsx`, `.ts`, `.tsx` and special handling for React/Jest are excluded. CommonJS and ESM exports are included. Global script public exposure may need runtime verification.
4. **Static AST graph:** actual resolved usage is L1, unused import/side-effect relationships may be conservatively L2. Do not create an actual-use dependency because symbols merely share a file. Dynamic imports, computed exports, bundler aliases and runtime indirection require warnings when unresolved; no fabricated internal edges.
5. **Vitest only:** MATMA `impact` returns test paths; it does not execute Vitest. Generated tests deliberately throw until meaningful assertions exist, and missing tests are reported separately. No production-file changes are authorized.
6. **Strict centralized mocks:** mock behavior must be explicitly supplied; unconfigured calls fail loudly instead of returning accidental undefined. `fetch` mocks must support HTTP error statuses (Response resolves with `ok=false`), network rejection, timeout/abort, invalid data, plus successful scenarios. Authored tests must actually assert the application's response to applicable failures. Each API mock belongs in the shared `tests/mocks/mirror/` registry.
7. **Injection and unmockable closures:** if a direct lexical same-module reference cannot be replaced through a public import mock, report `injection_seam_review`. A private helper may be part of the public unit's implementation; otherwise propose a real DI seam and ask for authorization, never fake isolation. Do not rewrite production code without consent.
8. **Snapshots/selection:** index generates owned `.auto.yaml` and preserves previous/current symbol fingerprints. Changes propagate along the union of old/new edges, with cycle-safe shortest weighted impact. `context` reads only symbol-owned source regions. Missing/stale index must fail; no AST reparse during impact.
9. **Safety:** never overwrite authored tests, mock files or production source. Skills are instructional copies: installing a skill does not install the MATMA CLI, enable a provider, run tests or grant live-service approval.
